================================================================================
KEY INSIGHTS DOCUMENTED
================================================================================

1. Why LoRA on FFN only?
   - FFN stores factual knowledge
   - Attention handles reasoning
   - Preserves model capabilities

2. Why data augmentation?
   - Document rewriting: diversity
   - QA generation: explicit supervision
   - Combined: better generalization

3. Why three training stages?
   - With original doc: learn to use context
   - With rewrite: increase diversity
   - Without doc: memorize to parameters

4. Why concatenation merging?
   - Each doc gets independent subspace
   - Linear combination of knowledge
   - Equivalent to higher-rank LoRA

5. Three inference methods compared:
   - ICL: Flexible but slow
   - PRAG: Fast but fixed knowledge
   - Combine: Best accuracy, moderate speed

REPRODUCTION WORKFLOW DOCUMENTED
================================================================================

Complete Pipeline:
1. Environment Setup (conda, pip, paths)
2. Data Preparation:
   a. Elasticsearch setup + Wikipedia indexing
   b. Download QA datasets
   c. Run data augmentation
3. Optional: LoRA warmup training
4. Document Parameterization:
   a. For each question
   b. For each retrieved document
   c. Train separate LoRA adapter
5. Inference and Evaluation:
   a. Load relevant LoRAs
   b. Merge using concatenation
   c. Generate and evaluate answers

Estimated Time:
- Minimum: 1-2 days (with pre-processed data)
- Full pipeline: 2-3 days (from scratch)

Hardware Requirements:
- Minimum: 24GB GPU, 32GB RAM, 100GB disk
- Recommended: 48GB GPU, 64GB RAM, 200GB disk

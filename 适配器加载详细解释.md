# 详细解释：为什么适配器加载失败以及如何修复

## 问题根源详解

### 路径结构

您的LoRA权重路径是：
```
offline/.../data_0/passage_0/adapter_model.safetensors
```

这个路径**本身没有问题**！真正的问题在于**如何加载**这个文件。

### 问题的本质：参数名称不匹配

让我用具体例子说明：

#### 场景1：Encode阶段（训练并保存适配器）

**encode.py 第104行**：
```python
model = PeftModel.from_pretrained(model, init_adapter_path, is_trainable=True)
# 注意：没有指定 adapter_name 参数！
```

当您**保存**这个模型时（第117行）：
```python
model.save_pretrained(save_path)  # save_path = "offline/.../data_0/passage_0/"
```

保存的参数文件 `adapter_model.safetensors` 中的参数名称是：
```
base_model.model.model.layers.0.mlp.gate_proj.lora_A.weight
base_model.model.model.layers.0.mlp.gate_proj.lora_B.weight
base_model.model.model.layers.0.mlp.up_proj.lora_A.weight
base_model.model.model.layers.0.mlp.up_proj.lora_B.weight
...
```

**关键点**：参数名中**没有**数字后缀（如 `.0.weight`）

#### 场景2：Inference阶段（您当前的错误代码）

**您当前的 inference.py 第85行**：
```python
model = PeftModel.from_pretrained(
    model, 
    adapter_path,
    adapter_name = "0",  # ❌ 问题就在这里！
    is_trainable = False
)
```

当您**指定** `adapter_name="0"` 时，PEFT期望加载的参数名称是：
```
base_model.model.model.layers.0.mlp.gate_proj.lora_A.0.weight  # 注意有 .0
base_model.model.model.layers.0.mlp.gate_proj.lora_B.0.weight  # 注意有 .0
base_model.model.model.layers.0.mlp.up_proj.lora_A.0.weight
base_model.model.model.layers.0.mlp.up_proj.lora_B.0.weight
...
```

**关键点**：期望的参数名中**有** `.0` 后缀

### 不匹配的结果

```
保存时的参数名：lora_A.weight, lora_B.weight
期望的参数名：  lora_A.0.weight, lora_B.0.weight

结果：找不到匹配的参数！
```

这就是为什么您看到警告：
```
UserWarning: Found missing adapter keys while loading the checkpoint: 
['base_model.model.model.layers.0.mlp.gate_proj.lora_A.0.weight', ...]
```

PEFT找不到带 `.0` 后缀的参数，所以适配器实际上是**空的**或使用**随机初始化**！

## 具体修复方案

### 修复后的完整 inference.py 代码

将您的 inference.py 中的第78-101行替换为以下代码：

```python
            else:
                # Load adapters for each passage
                # IMPORTANT: Don't specify adapter_name to match how they were saved during encoding
                for pid in range(len(passages)):
                    adapter_path = os.path.join(load_adapter_path, filename, f"data_{test_id}", f"passage_{pid}")
                    if pid == 0:
                        # ✅ 关键修复：不指定 adapter_name
                        model = PeftModel.from_pretrained(
                            model, 
                            adapter_path,
                            is_trainable = False
                        )
                        # 获取PEFT自动分配的适配器名称
                        first_adapter_name = model.active_adapter if hasattr(model, 'active_adapter') else "default"
                    else:
                        # 为后续适配器使用唯一名称
                        model.load_adapter(adapter_path, adapter_name = f"adapter_{pid}") 
                
                # 获取所有已加载适配器的实际名称
                if hasattr(model, 'peft_config'):
                    adapter_names = list(model.peft_config.keys())
                else:
                    # 如果无法获取，使用默认假设
                    adapter_names = ["default"] + [f"adapter_{i}" for i in range(1, len(passages))]
                
                # merge
                num_adapters = len(passages)
                model.add_weighted_adapter(
                    adapters = adapter_names[:num_adapters],  # ✅ 使用实际的适配器名称
                    weights = [1.0 / num_adapters] * num_adapters,
                    adapter_name = "merge", 
                    combination_type = "linear",
                )
                model.set_adapter("merge")
                ret.append(get_pred(model, psgs=None if args.inference_method == "prag" else passages))
                model.delete_adapter("merge")
                model = model.unload()
                torch.cuda.empty_cache()
                gc.collect()
```

### 关键修改点对比

| 位置 | 您的代码（错误） | 修复后的代码（正确） |
|------|----------------|---------------------|
| 第85行 | `adapter_name = "0"` | **移除此参数** |
| 第89行 | 无 | `model.load_adapter(..., adapter_name=f"adapter_{pid}")` |
| 第93行 | `adapters = [str(i) for i in range(num_adapters)]` | `adapters = adapter_names[:num_adapters]` |

### 为什么这样修复？

1. **第一个适配器（pid=0）**：
   - 不指定 `adapter_name`，让PEFT使用默认命名
   - 这样参数名就是 `lora_A.weight`，与保存时一致 ✅

2. **后续适配器（pid=1,2）**：
   - 必须指定唯一的 `adapter_name`（如 `adapter_1`, `adapter_2`）
   - 因为我们要加载多个适配器到同一个模型中

3. **合并时使用实际名称**：
   - 不能假设名称是 "0", "1", "2"
   - 而要使用实际加载后的名称（通常是 "default", "adapter_1", "adapter_2"）
